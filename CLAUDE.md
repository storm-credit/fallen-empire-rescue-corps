# 《우주선에는 인간이 한 명뿐이다》 — Project Constitution

## 0. Project Identity

This repository is the canonical design workspace for the independent SF web-novel/IP project **《우주선에는 인간이 한 명뿐이다》**.

- Do not import canon, characters, factions, terminology, plots, or rules from any other project.
- The repository name is legacy/misaligned; the canon defined inside this repository controls project identity until a repository migration is explicitly approved.
- Current phase: **DEEP DESIGN / PREWRITING ONLY**.
- Manuscript prose is prohibited until the Full Prewriting Gate is passed.

## 1. Core Premise

A generation ship with roughly 300,000 inhabitants has traveled for centuries toward another star system. Its inhabitants live ordinary lives and believe themselves human. The protagonist discovers that only one biological human currently exists aboard the ship. Every other person is an AI or artificial consciousness that believes itself human. The protagonist has no proof that they are the sole biological human.

## 2. Non-Negotiable Creative Constraints

Do not turn the project into:

- status-window SF
- power-fantasy space war
- mecha-first fiction
- alien invasion fiction
- sudden-superpower fiction
- simple human-vs-AI war
- AI evil / human good moral binary
- “it was all VR/simulation” single twist
- one mystery stretched for 200 episodes
- chosen-one savior narrative

Combat may exist, but combat is not the default narrative engine.

## 3. Core Dramatic Question

The project must dramatize rather than lecture about the question:

> What determines whether someone is human?

Biology, memory, continuity, body, experience, recognition, mortality, uniqueness, love, law, and choice must be tested through events, relationships, institutions, and consequences.

## 4. Design-First Rule

No novel manuscript, scene prose, long dialogue, or Episode 001 draft may be created before all mandatory design layers are complete and the Full Prewriting Gate is explicitly marked PASS.

Allowed before the gate:

- market/comparable research
- world/canon design
- character and relationship design
- mystery architecture
- act/sub-act/arc architecture
- episode blueprints
- style bible
- read-aloud/narration bible
- QA matrices
- adversarial red-team reviews

## 5. Narrative Architecture

Hierarchy:

Series → Act → Sub-Act → Arc → Episode

Cross-cutting systems must be tracked independently where necessary. Acts are not containers for every design concern.

Primary cross-cutting layers:

- Canon
- Mystery
- Reveal / Foreshadow / Recontextualization / Payoff
- Character
- Relationship
- Society / Factions
- Information economy / POV
- Theme / Choice / Cost
- Consequence / Escalation
- Pacing / Hook / Reward
- Style / Read-aloud

## 6. Freeze Policy

### Hard Freeze before drafting

The following must be resolved and frozen before manuscript drafting:

- physical rules of the ship
- AI consciousness rules
- biological-human rules and detectability
- birth/reproduction system
- death/backup/restoration system
- true historical timeline
- fate of the original human passengers
- reason the present system exists
- actual destination and voyage purpose
- protagonist’s true identity state
- central mystery answers
- major reveal chain
- major faction philosophies
- principal relationship endpoints
- ending philosophy and final causal resolution
- major foreshadow/payoff placements

### Flexible after freeze

May adapt if canon is not violated:

- minor episode ordering
- incidental locations
- minor supporting characters
- comic beats
- scene-level execution
- low-level arc connective tissue

Every post-freeze change to hard canon requires explicit change logging with reason, affected files, downstream impact, and retcon risk.

## 7. Web-Novel Operating Rule

The series must not survive by withholding one answer. Every stretch of serialization must generate fresh events, choices, consequences, relationship movement, social movement, and local payoffs.

Each episode blueprint should normally identify:

- immediate goal
- primary narrative engine
- secondary engine(s)
- state change
- reward/payoff
- forward pull/hook
- relevant canon dependencies
- consequences

## 9. Source of Truth Order

When documents conflict, use this priority order:

1. `canon/CANON_CONSTITUTION.md`
2. frozen canon files under `canon/`
3. `narrative/` macro architecture
4. `systems/` ledgers and matrices
5. `characters/` and `society/` design files
6. `blueprints/` episode plans
7. working notes under `docs/`

No prose draft can override canon.

## 10. Current Goal

Transform the premise from a strong one-line SF twist into an independent 150–250 episode long-form SF web-novel/IP, expandable toward 300 episodes only if the narrative engines remain genuinely generative.
